# Test Plan — Arkanoid Quiz

**Версия:** 1.0  
**Дата:** 27-05-2026  
**Тестировщик:** [Система]  
**Ветка:** `feature/quiz-mechanics`

---

## 1. Введение

Данный документ определяет стратегию, цели, объём и подходы к тестированию игры **Arkanoid** на Python/pygame с элементами обучения — при потере мяча игрок должен ответить на вопрос, чтобы продолжить игру.

Тестирование проводится на основе:
- Кода из файла `test_game.py` (существующие тесты)
- Модулей: `Ball`, `Paddle`, `Brick`, `Bonus`, `Arkanoid`, `Quiz`, `Progress`
- Констант из `classes.constants`
- Системы сохранения прогресса (JSON)
- Механики викторины с повторным использованием вопросов

---

## 2. Цели тестирования

| № | Цель |
|---|------|
| 1 | Проверить базовую физику арканоида: движение мяча, отскоки от стен, платформы |
| 2 | Проверить поведение кирпичей: уменьшение прочности, изменение цвета, уничтожение |
| 3 | Проверить бонусы: падение, типы (доп. жизнь, многомячье, большая платформа) |
| 4 | Проверить загрузку уровней из JSON и fallback-генерацию |
| 5 | Проверить сохранение и загрузку прогресса (разблокированные уровни, рекорды) |
| 6 | Проверить механику викторины: выбор вопросов по темам, учёт использованных вопросов, цикличность |
| 7 | Проверить интеграцию викторины с игровым циклом (после потери мяча) |

---

## 3. Объём тестирования (Scope)

### В объёме (In Scope)

**Ball (мяч)**
- Начальная позиция и скорость
- Обновление координат
- Отскок от левой, правой стен и потолка
- Определение выхода за экран
- Синхронизация `rect` с координатами

**Paddle (платформа)**
- Начальная ширина и позиция
- Движение влево/вправо
- Границы экрана
- Увеличение платформы (бонус)
- Таймер возврата к нормальному размеру
- Обновление таймера

**Brick (кирпич)**
- Начальная прочность (`strength`)
- Уменьшение прочности при ударе
- Уничтожение кирпича при `strength == 1`
- Изменение цвета (красный → оранжевый → жёлтый)
- Размеры кирпича (70×22)

**Bonus (бонус)**
- Падение вниз
- Типы: `BONUS_EXTRA_LIFE`, `BONUS_MULTI_BALL`, `BONUS_BIG_PADDLE`
- Активность по умолчанию
- Размеры бонуса (20×20)

**Level Loading (загрузка уровней)**
- Загрузка 10 уровней из `levels.json`
- Чтение `layout` уровня
- Генерация уровней по умолчанию при отсутствии файла

**Progress Persistence (сохранение прогресса)**
- Сохранение и загрузка `unlocked_levels`, `high_scores`
- Сохранение `selected_topic` и `quiz_used_indices`
- Установка значений по умолчанию при отсутствии файла

**Quiz (викторина)**
- Выбор вопросов из общей базы
- Выбор вопросов по выбранной теме (`selected_topic`)
- Fallback на общие вопросы при неизвестной теме
- Активация викторины (`_start_quiz`)
- Завершение викторины: правильный ответ → восстановление жизни, неправильный → `game_over`
- Учёт использованных вопросов (`quiz_used_indices`)
- Циклический перебор вопросов после использования всех
- Независимые счётчики для разных тем

**Вспомогательные функции**
- `wrap_text`: разбиение длинного текста на строки

### Вне объёма (Out of Scope)

- Визуальный рендеринг (pygame display)
- Обработка реального пользовательского ввода (клавиатура/мышь)
- Аудиоэффекты
- Сетевая многопользовательская игра
- Производительность и нагрузочное тестирование

## 4. Виды тестирования

| Вид | Что проверяем | Инструмент |
|-----|---------------|------------|
| **Модульное (Unit)** | `Ball`, `Paddle`, `Brick`, `Bonus` — изолированно | pytest |
| **Интеграционное** | `Arkanoid` + загрузка уровней + сохранение прогресса + викторина | pytest + `tmp_path` |
| **Негативное** | Отсутствие файлов, пустые вопросы, неизвестные темы | pytest |
| **Функциональное** | Механика викторины (цикл вопросов, восстановление жизни) | pytest |

> Всё тестирование **автоматизировано** через pytest с использованием `tmp_path` для изоляции файловой системы.

## 7. Приоритеты дефектов

| Приоритет | Описание | Примеры |
|-----------|----------|---------|
| **P1 — Критический** | Игра падает или викторина не запускается | `_start_quiz()` вызывает исключение, `game_over` не наступает при потере мяча |
| **P2 — Высокий** | Неправильная логика вопросов или прогресса | Неправильный учёт использованных вопросов, восстановление жизни при неверном ответе |
| **P3 — Средний** | Отклонение от спецификации, но игра работает | Неверный цвет кирпича, некорректное обновление таймера платформы |
| **P4 — Низкий** | Косметические / форматирование | `wrap_text` разбивает неоптимально, но работает |

## 8. Риски

| Риск | Митигация |
|------|-----------|
| Тесты используют `pygame.display.set_mode((1, 1))` — может не работать в CI без дисплея | Установлены `SDL_VIDEODRIVER=dummy` и `SDL_AUDIODRIVER=dummy` |
| Конфигурационные пути (`CONFIG_DIR`) изменяются глобально в тестах | Используется контекстный менеджер `_config_dir` для восстановления после теста |
| Зависимость от реальных JSON-файлов | Тесты используют `tmp_path` фикстуру pytest для изоляции |
| Отсутствие тестов на интеграцию `Arkanoid` с викториной в полном цикле | Существующие тесты проверяют `_finish_quiz` и `_start_quiz` изолированно, но не полный игровой цикл |
