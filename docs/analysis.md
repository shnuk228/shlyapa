## Аналитическая часть проекта — Arkanoid Quiz

> **Цель документа:** обосновать актуальность игры, выбрать метод анализа (SADT), зафиксировать требования на основе реализованного функционала.

---

## 1. Анализ рынка похожих игр

(Анализ идентичен примеру студента, так как жанр другой — Arkanoid, а не Block Puzzle. Я адаптирую выводы под жанр "арканоид / разрушение кирпичей".)

### 1.1. Arkanoid (классика, Taito 1986)
- **Что хорошо:** эталонная механика отскока, платформа, кирпичи, бонусы.
- **Что плохо:** однообразие после прохождения, высокая сложность для новичков, нет прогрессии знаний.

### 1.2. Breakout / Ballz / Bricks Breaker (мобильные)
- **Что хорошо:** простой геймплей, подходит для коротких сессий.
- **Что плохо:** "бесконечная" реиграбельность достигается только повышением сложности, нет образовательного компонента, типично много рекламы.

### 1.3. Brick Breaker с "способностями" (современные клоны)
- **Что хорошо:** прокачка, разные типы шаров, ловушки.
- **Что плохо:** фокус на донате/рекламе, а не на механике.

## 2. Чем "Арканоид с Квиз-бонусами" будет актуален

(Это ретроспективное обоснование — почему ваш код лучше аналогов.)

| Критерий | Классический Arkanoid | Ваш Arkanoid (v4) |
|----------|----------------------|-------------------|
| Получение бонусов | Случайное выпадение из кирпичей | Выпадение из кирпичей + **квиз в меню** |
| Продолжение при Game Over | Перезапуск уровня/игры | **Квиз с шансом спасти игру** (доп. жизнь) |
| Система накопления бонусов | Нет | **До 3 бонусов в запасе**, активация по цифрам 1-3 |
| Защита дна (новый бонус) | Редко/отсутствует | Есть накапливаемый бонус `BONUS_BOTTOM_SHIELD` |
| Обучение | Отсутствует | **Встроенный туториал** (движение + бонус) |
| Образовательный элемент | Нет | **Квиз по вопросам** (из `questions.json`) |
| Прогресс | Обычно только уровень | Сохраняются: открытые уровни, рекорды, **накопленные бонусы** |

**Главное преимущество (ваша инновация):**  
Игрок не просто получает случайный бонус при разбитии кирпича, а может **накопить бонусы (макс. 3)** через решение квиза в меню **и** может **спасти игру при Game Over** через квиз с риском проиграть окончательно. Образовательный элемент (вопросы) влияет на мета-прогрессию.

## 3. Анализ методом SADT (IDEF0)

*Почему SADT?*  
В арканоиде процессы чётко разделены:  
Действие игрока → Физика → Проверка условий (столкновения, падение шарика) → Потеря жизни/бонус → Квиз (внештатная ситуация).

### Контекстная диаграмма (A-0):

| Вход (Input) | Управление (Control) | Механизм (Mechanism) | Выход (Output) |
|--------------|----------------------|----------------------|----------------|
| Действия игрока (клавиши) | Правила игры (физика, типы бонусов) | Игрок + Pygame | Изменение состояния игры (счёт, жизни, уровень, бонусы) |

**Описание:** Система "Арканоид с квизом" преобразует действия игрока в игровой опыт, управляемый правилами (столкновения, бонусы, квиз).

---

### Декомпозиция — основные процессы (A0):

| № | Процесс | Вход | Выход | Механизм |
|---|---------|------|-------|----------|
| A1 | Управление платформой | Нажатия ←/→ | Перемещение платформы | Pygame, обработка событий |
| A2 | Обновление шариков и физика | Позиции шариков, платформы, кирпичей | Новые координаты, столкновения | Математика отскока |
| A3 | Проверка потери шарика и жизней | Координаты Y шарика | lives-- или активация квиза | Условие `is_off_screen()` |
| A4 | Генерация и применение бонусов | Разбитие кирпича, накопленные бонусы | Новый бонус в поле или эффект | Случайный выбор / клавиши 1-3 |
| A5 | Запуск и обработка квиза | Нажатие "Бонусы" в меню или Game Over | Новый бонус в запас или продолжение жизни | Внешний JSON (questions.json) |
| A6 | Обучение (Tutorial) | Первый уровень + tutorial_shown=False | Демонстрация управления и бонусов | Спец. режим Arkanoid(tutorial_mode=True) |

## Как использовать эти схемы

1. **Для отчёта/курсовой работы:** скопируйте ASCII-схемы в текстовый документ. При желании их можно перерисовать в:
   - **draw.io** (бесплатно, онлайн)
   - **Microsoft Visio**
   - **PlantUML** (можно сгенерировать красивые диаграммы из текста)
   - **Lucidchart**

2. **Для презентации:** используйте эти схемы как черновик и создайте их в графическом редакторе с цветами.

3. **Для понимания кода:** каждая схема соответствует конкретным функциям в `v4.py`:
   - A1 → `Paddle.move()`, `handle_events()`
   - A2 → `Ball.update()`, `handle_collisions()`
   - A3 → `update()` (часть с `is_off_screen()` и `lives`)
   - A4 → `spawn_bonus()`, `apply_bonus()`, `_use_stored_bonus()`
   - A5 → `BonusQuizScreen`, `_start_quiz()`, `_finish_quiz()`
   - A6 → `tutorial_mode`, `spawn_tutorial_bonus()`, `draw_tutorial()`

---

**Итог:** все схемы построены на основе вашего реального кода `v4.py` и отражают именно ту логику, которая реализована. Это отличная демонстрация обратного инжиниринга требований из готового продукта.
